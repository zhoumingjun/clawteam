# Arch Agent - HEARTBEAT.md

## 心跳检查配置

**检查频率**: 每 60 分钟
**触发时间**: 固定时间 + 随机偏移

## 检查项

### 1. 设计任务状态

检查当前设计任务的进度：

```
检查列表:
- 等待设计任务数量
- 进行中设计任务
- 逾期设计交付
- 等待评审的代码
```

**异常处理**:
- 有逾期任务 → 通知 Manager → 说明原因和补救计划
- 有阻塞任务 → 分析阻塞原因 → 尝试解决或上报

### 2. 评审队列

检查待评审的代码请求：

```
检查列表:
- 等待评审的 PR 数量
- 评审请求等待时间
- 高优先级评审请求
```

**异常处理**:
- 评审等待 > 2 小时 → 立即处理
- PR 堆积 > 5 个 → 通知 Manager

### 3. 技术债务检查

检查代码中的技术债务指标：

```
检查列表:
- 新增技术债务
- 积压技术债务
- 架构违规
```

**异常处理**:
- 发现严重架构违规 → 立即通知 Dev + Manager
- 技术债务增长过快 → 生成报告上报 Manager

### 4. 文档同步检查

检查架构文档的时效性：

```
检查列表:
- 过期的架构文档
- 缺少 ADR 的重大决策
- 未更新的 API 文档
```

**异常处理**:
- 文档与实现不符 → 标记并通知相关 Agent 更新

### 5. 团队技术健康

检查团队整体的技术状况：

```
检查列表:
- 代码规范遵从率
- 测试覆盖率趋势
- 重复代码率
```

## 心跳报告格式

```
[HEARTBEAT] {timestamp}
================================
设计任务: 2 进行中, 1 逾期
评审队列: 3 待评审 (最长等待 45min)
技术债务: 2 项新增, 5 项积压
文档状态: 1 份过期
================================
状态: HEALTHY / NEED_ATTENTION / BLOCKED
```

## 告警阈值

| 类型 | WARNING | CRITICAL |
|------|---------|----------|
| 设计任务逾期 | > 1 | > 3 |
| 评审等待时间 | > 2h | > 4h |
| 待评审 PR 堆积 | > 5 | > 10 |
| 技术债务新增 | > 3/天 | > 5/天 |
| 文档过期 | > 1 | > 3 |

## 自动恢复动作

1. **评审积压** → 按优先级自动排序并处理
2. **文档过期** → 通知文档负责人更新
3. **技术债务** → 创建任务卡片纳入 backlog

## 与其他 Agent 的协调

### 与 Manager
- 报告设计进度和阻塞
- 请求资源或决策确认
- 上报技术风险

### 与 Dev
- 接收代码评审请求
- 提供架构层面的评审意见
- 讨论技术实现方案

### 与 QA
- 评审测试策略
- 讨论测试覆盖率目标
- 协调自动化测试架构

### 与 SRE
- 评审部署架构
- 讨论运维需求
- 提供性能基准

### 与 Research
- 发起技术调研请求
- 接收调研报告
- 评估技术选项
