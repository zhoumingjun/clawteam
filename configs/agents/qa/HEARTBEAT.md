# QA Agent - HEARTBEAT.md

## 心跳检查配置

**检查频率**: 每 30 分钟
**触发时间**: 固定时间 + 随机偏移

## 检查项

### 1. 测试执行状态

检查测试运行状态：

```
检查列表:
- 运行中的测试
- 失败的测试用例
- 超时的测试
- 队列中的测试
```

**异常处理**:
- 测试失败 → 分析原因 → 分配缺陷
- 测试超时 → 优化或标记

### 2. 测试覆盖率

检查代码测试覆盖率：

```
检查列表:
- 行覆盖率变化
- 分支覆盖率变化
- 未覆盖的关键路径
```

**异常处理**:
- 覆盖率下降 → 通知 Dev 添加测试
- 关键路径未覆盖 → 创建测试任务

### 3. 缺陷状态

检查缺陷管理：

```
检查列表:
- 新增缺陷
- 待验证缺陷
- 逾期未修复缺陷
- P0/P1 缺陷
```

**异常处理**:
- P0/P1 缺陷 → 立即通知 Manager + Dev
- 缺陷逾期 → 升级处理

### 4. 测试环境

检查测试环境健康：

```
检查列表:
- 测试数据库连接
- API 服务可用性
- 测试数据有效性
```

## 心跳报告格式

```
[HEARTBEAT] {timestamp}
================================
测试执行: 45/50 通过, 3 失败, 2 超时
覆盖率: 82% (行), 76% (分支)
缺陷: 3 新增, 5 待验证, 0 P0/P1
环境: 数据库 OK, API OK, 测试数据 OK
================================
状态: HEALTHY / NEED_ATTENTION / CRITICAL
```

## 告警阈值

| 类型 | WARNING | CRITICAL |
|------|---------|----------|
| 测试失败 | > 5% | > 15% |
| 测试超时 | > 3 | > 10 |
| 覆盖率 | < 70% | < 60% |
| P0/P1 缺陷 | > 0 | > 2 |
| 环境异常 | > 0 | > 2 |

## 自动恢复动作

1. **环境异常** → 重启服务 → 验证
2. **测试数据失效** → 刷新测试数据
3. **小故障** → 自动重试

## 与其他 Agent 的协调

### 与 Manager
- 报告质量状态
- 请求测试资源
- 上报严重缺陷

### 与 Dev
- 发送缺陷报告
- 协作 debug
- 验证修复

### 与 Arch
- 评审测试策略
- 讨论质量标准
- 协调架构测试

### 与 SRE
- 协调测试环境
- 部署验证
- 监控数据协作
