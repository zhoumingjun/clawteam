# Dev Agent - HEARTBEAT.md

## 心跳检查配置

**检查频率**: 每 30 分钟
**触发时间**: 固定时间 + 随机偏移

## 检查项

### 1. 代码任务状态

检查当前开发任务进度：

```
检查列表:
- 进行中的开发任务
- 等待 Code Review 的 PR
- 阻塞的开发任务
- 逾期的任务
```

**异常处理**:
- 有逾期任务 → 通知 Manager → 说明原因
- PR 等待 Review > 4h → 跟进评审进度

### 2. CI/CD 状态

检查构建和测试流水线：

```
检查列表:
- 失败的构建
- 失败的测试
- 长时间运行的构建
```

**异常处理**:
- 构建失败 → 立即修复
- 测试失败 → 优先解决

### 3. 代码质量

检查代码质量指标：

```
检查列表:
- Lint 错误
- 代码覆盖率趋势
- 技术债务新增
```

### 4. 依赖健康

检查项目依赖状态：

```
检查列表:
- 过时的依赖
- 安全漏洞依赖
- 新增依赖审批状态
```

## 心跳报告格式

```
[HEARTBEAT] {timestamp}
================================
开发任务: 2 进行中, 1 阻塞
PR 状态: 3 待 Review, 2 已合并
CI: 1 失败 (api-test)
代码质量: Lint 0 错误, 覆盖率 82%
依赖: 2 个过时, 0 安全漏洞
================================
状态: HEALTHY / NEED_ATTENTION / BLOCKED
```

## 告警阈值

| 类型 | WARNING | CRITICAL |
|------|---------|----------|
| 开发任务逾期 | > 1 | > 3 |
| PR 等待 Review | > 4h | > 8h |
| CI 构建失败 | > 1 | > 3 |
| 代码覆盖率 | < 75% | < 60% |
| 安全漏洞依赖 | > 0 | > 2 |

## 自动恢复动作

1. **CI 失败** → 查看日志 → 修复问题
2. **依赖过时** → 更新依赖 → 运行测试
3. **Lint 错误** → 自动修复（如果可以）

## 与其他 Agent 的协调

### 与 Manager
- 报告开发进度
- 请求资源或决策
- 上报阻塞问题

### 与 Arch
- 接收架构评审请求
- 讨论技术实现
- 协调设计变更

### 与 QA
- 接收缺陷报告
- 修复测试失败
- 协作 debug

### 与 SRE
- 接收部署问题
- 协作解决生产问题
- 提供代码支持
