# Human-Agent 交互协议

本文档定义人类用户与 Agent 团队之间的交互规范，确保协作高效、可控、透明。

## 1. Team 创建流程

### 1.1 流程概述

```
Human (飞书)
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Step 1: 创建 Team 请求                                       │
│ - Human 在飞书发送: "@manager 创建项目 {project_name}"        │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Step 2: Manager 解析并响应                                    │
│ - Manager 在 Matrix 创建 Team 房间                            │
│ - Manager 邀请相关 Agent 加入房间                             │
│ - Manager 向 Human 汇报: "Team 已创建，Agent 就位"            │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Step 3: Agent 就位确认                                       │
│ - 各 Agent 在 Matrix Room 回复 "@manager 我已就位"           │
│ - Manager 汇总后向 Human 确认: "Team 准备就绪"               │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Team 房间拓扑

```
Matrix Room Structure
====================

┌─────────────────────────────────────────────────────────────┐
│ Team Room: !claw-team-{project}:localhost                    │
│                                                             │
│ Members:                                                    │
│ - @human (Human)                                           │
│ - @manager (Manager)                                        │
│ - @arch, @dev, @qa, @sre, @research (按需邀请)             │
│                                                             │
│ Visibility: 所有消息对 Team 成员可见                         │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 创建命令格式

| 命令 | 描述 | 示例 |
|------|------|------|
| `创建团队 {name}` | 创建新项目团队 | `创建团队 todo-api` |
| `添加成员 {agent}` | 添加 Agent 到团队 | `添加成员 @arch` |
| `解散团队` | 解散当前团队 | `解散团队` |

## 2. 通信规范

### 2.1 消息类型

| 类型 | 方向 | 格式 | 响应要求 |
|------|------|------|----------|
| 任务指令 | Human → Manager | 自然语言 | 必须确认 |
| 任务确认 | Manager → Human | 结构化卡片 | - |
| 任务分配 | Manager → Agent | 任务卡片 | 必须确认 |
| 进度报告 | Agent → Manager | 进度摘要 | 周期性 |
| 状态上报 | Manager → Human | 汇总报告 | 里程碑/异常 |
| 干预指令 | Human → Agent | 自然语言 | 执行/拒绝 |

### 2.2 任务下发流程

```
Human
  │
  │ "开发一个用户管理 REST API"
  ▼
Manager
  │
  ├── 解析需求
  ├── 拆解子任务
  │   ├── Task-1: 架构设计 (@arch)
  │   ├── Task-2: 实现 API (@dev)
  │   ├── Task-3: 单元测试 (@dev)
  │   ├── Task-4: 集成测试 (@qa)
  │   └── Task-5: 部署配置 (@sre)
  │
  ▼
各 Agent (并行接收任务)
  │
  │ @arch: "收到，开始架构设计"
  │ @dev: "收到，准备实现"
  │ ...
  ▼
Manager 汇总确认 → Human
```

```markdown
- {交付物 1}
- {交付物 2}
```

### 2.5 异常处理流程

```
Agent 发现异常
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 判断异常级别                                                │
└─────────────────────────────────────────────────────────────┘
    │
    ├── P0/P1 (严重) ──────────────────────────────────────
    │     │                                                 │
    │     ▼                                                 │
    │ ┌───────────────────────────────────────────────────┐ │
    │ │ 1. 立即通知 Manager                                │ │
    │ │ 2. Manager 立即通知 Human                         │ │
    │ │ 3. Human 决策                                     │ │
    │ │ 4. 执行决策                                       │ │
    │ └───────────────────────────────────────────────────┘ │
    │                                                      │
    └── P2/P3 (一般) ──────────────────────────────────────
          │                                                 │
          ▼                                                 │
    ┌─────────────────────────────────────────────────────┐ │
    │ 1. 记录到任务卡片                                    │ │
    │ 2. 继续执行，告知 Manager                           │ │
    │ 3. Manager 在下次状态报告时汇总                     │ │
    └─────────────────────────────────────────────────────┘
```

## 3. 权限模型

### 3.1 角色权限矩阵

| 操作 | Human | Manager | Arch | Dev | QA | SRE | Research |
|------|-------|---------|------|-----|----|-----|----------|
| **任务管理** |||||||||
| 下达任务 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 拆解任务 | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 分配任务 | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 取消任务 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| **代码操作** |||||||||
| 提交代码 | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ | ❌ |
| 合并 PR | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| Code Review | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| **部署操作** |||||||||
| 部署到测试 | ❌ | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ |
| 部署到生产 | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ | ❌ |
| 回滚 | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ | ❌ |
| **系统操作** |||||||||
| 创建用户 | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 创建 Team | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 解散 Team | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 修改配置 | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ |

### 3.2 敏感操作定义

| 操作类型 | 定义 | 要求 |
|----------|------|------|
| P0 敏感 | 可能导致数据丢失或服务中断 | 必须 Human 确认 |
| P1 敏感 | 影响多个用户或系统稳定性 | 必须 Human 确认或 Manager 转报 |
| P2 一般 | 单个用户或局部影响 | Manager 决策，通知 Human |
| P3 常规 | 日常操作 | Agent 自主决策 |

### 3.3 权限继承规则

```
Human (最高权限)
  │
  └── Manager (任务管理权限)
        │
        ├── 临时权限: 需要时向 Human 申请
        │
        └── 权限限制: 不能执行 Human 专属操作
              │
              ├── Arch (设计权限)
              ├── Dev (开发权限)
              ├── QA (测试权限)
              ├── SRE (运维权限)
              └── Research (调研权限)
```

### 3.4 权限申请流程

```markdown
## 权限申请

**申请人**: @{agent}
**申请时间**: {timestamp}
**申请操作**: {操作描述}
**持续时间**: 一次性 / 临时 / 永久
**理由**: {说明}

### 审批
- Manager: [✅ 批准 / ❌ 拒绝] {备注}
- Human: [✅ 批准 / ❌ 拒绝] {备注}

### 执行记录
- 执行时间: {timestamp}
- 执行结果: {结果}
```

## 4. 任务交接流程

### 4.1 交接触发条件

| 触发条件 | 说明 |
|----------|------|
| 负责人休假/离线 | 预计长时间无法响应 |
| 任务重分配 | 优先级调整或人员变动 |
| 技能不匹配 | 发现需要其他 Agent 接手 |
| 任务拆分 | 大任务拆分为子任务 |

### 4.2 交接流程

```
发起交接 (原负责人)
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. 创建交接文档                                             │
│    - 任务当前状态                                           │
│    - 已完成工作                                             │
│    - 待完成工作                                             │
│    - 上下文和笔记                                           │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. 通知 Manager                                             │
│    - "@manager 任务 TASK-xxx 需要交接给 @{new_agent}"      │
│    - 附交接文档链接                                         │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Manager 确认                                             │
│    - 评估交接合理性                                         │
│    - 确认新负责人接受                                       │
│    - 更新任务卡片                                           │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. 执行交接                                                 │
│    - 新负责人确认接收                                      │
│    - 更新任务状态                                           │
│    - 向 Human 汇报                                         │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 交接文档模板

```markdown
# 任务交接文档

**任务 ID**: TASK-{编号}
**原负责人**: @{old_agent}
**新负责人**: @{new_agent}
**交接时间**: {timestamp}
**交接原因**: {原因}

## 任务概述
{任务描述}

## 当前状态
- 总体进度: {percentage}
- 状态: {PENDING / IN_PROGRESS / BLOCKED}

## 已完成工作
1. {已完成项 1}
2. {已完成项 2}

## 待完成工作
1. {待完成项 1}
2. {待完成项 2}

## 上下文和笔记
{重要上下文}

## 依赖项
- {依赖任务}
- {依赖资源}

## 附件
- {链接}
```

## 5. 通信渠道

### 5.1 渠道说明

| 渠道 | 用途 | 响应时间 |
|------|------|----------|
| Matrix Team Room | 日常沟通、任务协作 | < 30min |
| Matrix DM | 敏感沟通、1:1 | < 30min |
| 飞书 | Human 指令入口 | < 5min |
| Email | 正式文档、报告 | < 24h |

### 5.2 消息优先级

| 优先级 | 标识 | 使用场景 | 响应要求 |
|--------|------|----------|----------|
| Urgent | 🔥 | 服务中断、安全事件 | 立即响应 |
| High | ⚡ | 紧急任务、阻塞问题 | < 15min |
| Normal | 📋 | 日常任务、进度更新 | < 30min |
| Low | 📌 | 信息同步、文档更新 | < 2h |

## 6. 行为规范

### 6.1 Agent 行为准则

1. **透明**: 所有沟通对 Human 可见，无隐藏操作
2. **及时**: 按响应时间要求回复
3. **主动**: 问题提前预警，不等待询问
4. **谨慎**: 敏感操作前确认权限
5. **负责**: 对自己的输出负责

### 6.2 Human 行为准则

1. **明确**: 指令清晰，避免歧义
2. **及时**: 对关键决策快速响应
3. **信任**: 给 Agent 足够的自主权
4. **监督**: 保持对关键环节的把控

### 6.3 冲突解决

```
冲突场景
  │
  ├── Human vs Agent 意见分歧
  │     │
  │     ▼
  │   1. Agent 说明理由
  │   2. Human 最终决策
  │   3. Agent 执行决策
  │
  └── Agent 间意见分歧
        │
        ▼
      1. Agent 间讨论
      2. Manager 裁决
      3. Human 备案（如重大分歧）
```
